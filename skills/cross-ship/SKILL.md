# za:cross-ship — issue を実装し、Claude と Codex のクロスレビューで仕上げる

GitHub issue を起点に、実装から「レビュー収束済みの PR」までを**途中の確認なしに**通しで
実行する。`za:ship` との違いは**レビューを 2 モデルで行うこと**だけ。

1. `za:fix-issue` — issue の実装とコミット
2. `za:pr` — PR の作成
3. `za:cross-review` — Claude と Codex のクロスレビューと修正・push（収束するまで繰り返す）

狙いは、単一モデルのレビューに残る見落とし（同じモデルは同じ癖で見落とす）を、独立した
別モデルの目で埋めること。レビューの中身（2 モデルの呼び出し方・指摘のマージ・収束条件・
片方が使えないときの縮退）は `za:cross-review` が所有する。このスキルでは再定義しない。

マージは**行わない**（取り消しの効きにくい操作であり、最終確認はユーザーに残すため）。
完了時に `/za:merge` を案内する。

各手順は対応するスキルを **Skill ツールで順に呼び出して**実行する。各スキルの手順・
参照ドキュメント（`docs/rules/`・`docs/PR.md` など）はそのスキル自身の指示に従う。

## 手順

### 0. レビュー体制を先に確かめる（実装を始める前に 1 回）

レビューが 2 モデルになるかどうかを、**着手前に**ユーザーへ伝えておく（最後になって
「実は 1 モデルだった」と分かるのを避けるため）。相手側 CLI の可用性だけを確認する。

```sh
command -v codex && codex --version && codex login status   # Claude Code で実行中の場合
command -v claude && claude --version && claude auth status  # Codex で実行中の場合
```

- 使える場合: そのままクロスレビューになる旨を伝えて進む。
- 使えない場合: **停止しない**。「相手側（codex / claude）が使えないため、レビューは
  ホスト単独の自己レビューになる」ことを伝えてから、そのまま手順 1 へ進む。実際の縮退判断と
  ユーザーへの通知は `za:cross-review` の手順 2 が改めて行う。

### 1. 実装する（`za:fix-issue`）

`za:fix-issue` を呼び出し、issue の実装とコミットまで行う。

### 2. PR を作成する（`za:pr`）

`za:pr` を呼び出し、手順 1 のブランチ・コミットから PR を作成する。以降のレビューでは
ここで得た **PR 番号**を使う。

### 3. クロスレビューする（`za:cross-review`）

`za:cross-review` を手順 2 の PR 番号を渡して呼び出す。観点の読み込み・2 モデルでのレビュー・
指摘のマージ・修正とコミット・収束の判定・ルール化まで、すべてそのスキルの手順に従う。

このフローでは**確認のために停止しない**（下記「ユーザー確認の扱い」）。`za:cross-review` が
指摘の採否を判断する際も、同じルールで自動的に決めて判断ログに残す。

## ユーザー確認の扱い（このフローでの上書きルール）

呼び出す各スキルには「ユーザーに確認する」ステップがあるが、この通し実行では**確認のために
停止しない**。`za:ship` と同じルールで進める:

- **推奨案がある確認**（PR 作成の承認、実装方針の選択など）: 自分が推奨する案をそのまま
  採用して先へ進み、**判断ログ**に記録する。
- **推奨案を立てられる曖昧さ**: issue 本文・既存コード・プロジェクトのルールから最も整合する
  解釈を選んで進め、判断ログに「他にあり得た解釈」も添える。
- **レビューの指摘対応**: 対応する/しないの判断も自動で行い、非対応は理由つきでログに残す。
- **レビュー体制の縮退**: 相手側 CLI が使えない場合も止めない。ユーザーに伝えたうえで
  自己レビューで続行する（`za:cross-review` の手順 2）。

ただし次は**判断ではなく前提の不成立**なので、自動で進めず停止して報告する:

- 指定された issue が見つからない・クローズ済み・引数が無い
- 作業ツリーに関係のない未コミット変更がある（混入を防ぐため）
- 現在のブランチがデフォルトブランチでなく、分岐元の判断がつかない
- push・PR 作成・CI などが失敗し、自動リトライで解消しない

## 判断ログ

通し実行中に自動採用した判断を、その場で記録して最後にまとめて出力する。形式は `za:ship`
と同じ:

```
## 自動採用した判断
| # | 場面 | 判断 | 理由 / 他にあり得た選択肢 |
|---|------|------|--------------------------|
| 1 | 実装方針 | 稼働時間は全置換APIにした | 既存の photo/work_location と同型のため。差分更新も可能だったが… |
| 2 | 指摘の採否 | codex 単独の「命名変更」指摘は非対応 | 既存コードの命名規約と衝突するため |
```

判断が一つも無ければ「自動採用した判断: なし」と報告する。ログは会話への出力のみで、
ファイルには残さない。

## 完了報告

最後に次をまとめて報告する:

- **成果物**: ブランチ名・コミット一覧・PR の URL とタイトル
- **クロスレビュー結果**: `za:cross-review` の完了報告（レビュー体制・対応した指摘 / 対応
  しなかった指摘（検出元つき）・ラウンド数と収束の有無・モデル別の傾向）をそのまま含める
- **自動採用した判断**: 上記の判断ログ
- **次の作業**: マージは `/za:merge <PR番号>` で行えることを案内する
